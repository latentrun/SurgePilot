# Demo Recording Guide

Record a truthful 60–120 second walkthrough of the reviewed launch candidate. The video is optional and must not be linked until the owner has reviewed the final upload.

## 1. Preparation

- Use a clean supported host and the documented installation path.
- Use only disposable, non-sensitive data and a low-load example.
- Confirm no credential, token, email, private IP, internal hostname, personal path, or private log is visible.
- Prepare the repository, docs, and release links from `repository-metadata.md`.

## 2. Suggested sequence

1. Open the repository and state the AI-authorship responsibility boundary.
2. Show the public site and user documentation.
3. Install the reviewed release and show the supported startup path.
4. Create the first Admin in the disposable environment.
5. Show Load Node readiness, run one authorized low-load test, and open its report.
6. Show the repository evidence and release links.
7. End on the repository URL without claiming a Star count.

Do not present synthetic Landing dashboard, Recent Test Runs, or Distributed load mesh values as live service data, topology, benchmark results, or repository evidence. Keep their required adjacent demonstration labels visible.

## 3. Encoding and review

Use a standard web-compatible format, readable captions, and a clear 720p presentation. Inspect duration, dimensions, codec, audio, and final frames before upload.

## 4. Acceptance before publication

- [ ] The hook is visible in the first eight seconds.
- [ ] Every product state shown came from the reviewed launch candidate.
- [ ] The human/AI boundary is visible or linked.
- [ ] Text is readable and captions match visible actions.
- [ ] No secret, personal data, private endpoint, or personal path appears.
- [ ] The final frame links to `https://github.com/latentrun/SurgePilot` without a Star count.
- [ ] The owner reviewed the master and final encode.

Only after these checks pass should the runbook record the final video URL.
