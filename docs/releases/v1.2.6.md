## Highlights

- Registration now requires matching passwords before submitting. The confirmation field includes
  an eye button to show or hide its value, including keyboard operation. See [PR #65](https://github.com/latentrun/SurgePilot/pull/65).
- Runtime builds download the unchanged JMeter 5.6.3 distribution from the Apache distribution CDN,
  addressing the archive-server download timeout observed in native amd64 validation.

## Install

Install this exact release, then start it from an interactive terminal:

```sh
curl -fsSL https://github.com/latentrun/SurgePilot/releases/download/v1.2.6/install.sh | sh
surgepilot up
```

## Upgrade

Official installed releases v1.0.0, v1.1.0, v1.2.3, and v1.2.5 are within the supported same-major
upgrade range. Back up PostgreSQL, MinIO, and other persistent volumes. Stop or finish active Runs
and Load Node initialization work, run the installation command above, then run `surgepilot up`.

The transition is forward-only. If migration or health validation fails, fix the target problem
and retry the same `surgepilot up`. SurgePilot does not downgrade the database or automatically
start the previous release after migration begins.

Existing Load Nodes retain their previous Runtime version. Explicitly reinitialize each required
Load Node before starting new Runs.

## Compatibility and breaking changes

- Registration confirmation is checked only in the frontend. Existing authentication APIs,
  credentials, and sessions are unchanged.
- JMeter remains at version 5.6.3. Explicit Runtime source and checksum overrides remain supported.
- Manually extracted bundles remain expert-managed and do not use the installed-release transition
  protocol.
- Breaking changes: None.
